# 汇编器规定

## 1. 汇编器与执行器是两个层次

游戏汇编器读取 `.asm` 和 `spec.isa`，把文字转换成字节；硬件执行的是这些字节。`const`、标签、`@`、`include`、数据字面值都不是 CPU opcode。`push/pop/call/ret` 则是当前 ISA 定义的多机器指令别名，实际产生机器码。

本文记录当前 ISA 与游戏手册的规定。具体游戏版本中尚未运行验证的错误处理（负数、溢出、重复符号等）单列为后续兼容性测试，不把我们未来执行器的选择反写成游戏事实。

## 2. 输入格式

当前 `.isa` 包含：

```text
[settings]
name = "Symphony"

[fields]
register
zr 0000
...
flags 1111

[instructions]
...
```

`name` 是架构名称，不定义 C ABI。没有指定 `endianness`，按游戏 **SETTINGS** 手册默认为 **big**。默认源码行注释标记为 `;` 和 `//`，块注释为 `/* ... */`，块注释不嵌套。

注意两套注释规则：`.isa` 中 `#` 引出指令说明，这是 ISA 定义格式；当前 `.asm` 的默认行注释没有 `#`。不要把参考 Melody 语言的 `#` 注释搬到 Symphony 汇编输出。

指令名、寄存器名和标点按当前 ISA 原样输出。兼容代码使用小写 mnemonic、`zr/r1..r13/sp/flags`、逗号和方括号；不依赖大小写折叠或额外寄存器别名。空格的可选/必选取决于 ISA 语法：手册规定单空白可选，连续空白要求实际出现空白；生成器应统一输出常规空格以避开差异。

## 3. 操作数与地址

### 3.1 寄存器

`mov r1, r2` 中寄存器名字替换成字段值 1 和 2，不为寄存器分配主内存地址。Register File 组件内部用 `index*4` 存放寄存器，是内部实现映射，不是 `load_32 [4]` 能访问 `r1` 的意思。

### 3.2 立即数

立即数编码在机器指令内部。所有当前显式数字立即数字段宽度均为 U16，运行时零扩展至 32 位。比如：

```asm
mov r1, 65535
```

只占 4 字节。构造任意 32 位常量应分高低半部：

```asm
mov r1, 4660
lsl r1, r1, 16
or r1, r1, 22136
; r1 = 0x12345678
```

不能把 `mov r1, 0x12345678` 当成已存在的自动扩展伪指令。当前 `mov` 定义只产生一个基础机器字。也不要依赖 `mov r1, -1` 的接受/截断策略来得到 32 位 -1；可用 `not r1, zr`。

源码已有十进制、`0x...` 及带下划线十六进制用法。汇编时表达式支持范围须独立验证，不能把虚拟操作数的表达式语法等同于每个汇编操作数都接受所有表达式。

### 3.3 标签

标签定义不占字节，值是**当前位置的字节偏移**。允许先引用后定义：

```asm
jmp next
nop
next:
out 7
```

从地址 0 装配时，`next=8`，不是 2 或 3。游戏手册展示独立一行的 `name:` 语法；生成器采用这个格式。游戏示例也有 `name: U32 value` 写法，但第一版生成器无需依赖它。

标签不是运行时字符串或自动指针解引用。例：

```asm
mov r1, text
load_8 r2, [r1]
stop:
jmp stop
text:
"A\0"
```

`mov` 得到字节地址，`load_8` 才读取字符 65。屏幕不会因 `\0` 自动结束，软件字符串函数可以约定以零结束。

当前标签可用位置：ALU 第三个操作数（不含 `cmp`）、`mov/neg/not` 的第二个操作数、立即数跳转、`call`。`cmp` 数字形式只标注 `(immediate)`，`load/store/pload/pstore` 的直接地址形式也只标注 `(immediate)`。不能凭它们在硬件上都使用相同 16 位位域，就假设当前游戏解析器也接受标签。需要时先 `mov` 标签地址到寄存器。

所有直接跳转/调用中的标签最终都只占 **16 位地址字段**，所以目标必须在 0..65535。即使标签本身是 32 位 PC 范围的偏移，也不能装进 16 位编码。`call` 虽未显式写 `:U16`，其位串只有 16 个 `a`，同样受此限制。

当前只有 `jmp` 定义了寄存器目标形式，没有 `call register` 和 `je register`。远地址调用、远条件跳转必须由后续编译器显式展开，不能虚构合法语法。项目汇编器会拒绝超出操作数位宽的地址。

## 4. 数据字面值

游戏手册说明 `U8 123` 把完整字节插入程序存储器，位宽可增大且必须为 8 的倍数。游戏本地 **ASM** 手册列出 U8/U16/U32/U64。未来汇编器若声明兼容该语法，就不能只认这四个宽度；任意合法宽度的实际数值上限仍需游戏版本验证。

```asm
U8 123
U16 4660
U32 305419896
"Hello"
```

按大端字节顺序，上述序列为：

```text
7B 12 34 12 34 56 78 48 65 6C 6C 6F
```

`"Hello"` 不自动追加 C 的 NUL；若需要结束符，写 `"Hello\0"` 或显式跟 `U8 0`。它不是一个“打印 Hello”的指令。

字符串里的 `;`、`//` 不应被词法器误当注释，不能先用简单 `split(';')` 处理整行。双引号字符串至少必须兼容现有 ASCII 文本及 `\0` 用法；其他转义、非 ASCII/UTF-8 的精确编码、最大宽度/整数容量属于待验证兼容性项。

字面值与立即数的区别：`out 123` 的 123 是一个基础指令内的 16 位字段；`U8 123` 是原样占据当前位置的一个数据字节，没有输出副作用。如果 PC 走入数据，CPU 仍会把那里的连续四字节当机器指令尝试执行。

没有隐式数据段、跳过数据、字符串结束或自动对齐。若插入 1 字节后继续写指令，后续位置就偏移 1 字节。生成器应显式安排控制流和对齐；在文档里区分“生成代码要求 4 字节对齐”和“当前硬件是否对非对齐取指报错”。

## 5. const

`const` 给寄存器或其他操作数命名，不分配存储，不产生机器码：

```asm
const RESULT = r1
mov RESULT, 7
```

`RESULT` 是 `r1` 的别名，不是常量地址或只能读不能写的 C 变量。数字常量同样是编译期符号；是否支持某个复杂表达式、循环定义或遮蔽规则，要单独核实。

不能依据函数调用的概念推断 `const` 自动有 C 式函数局部作用域。未来生成器用唯一前缀避免符号冲突。

## 6. @ 区段

`@地址` 将当前位置向前推进到绝对字节偏移，中间写入零：

```asm
U8 1
@0x8
U8 2
```

输出为 `01 00 00 00 00 00 00 00 02`。`@` 本身不占额外字节，地址 8 存放 2。

这不是 ELF section、运行时跳转或只声明虚拟地址的 `.org` 变种。零填充真实增加映像大小；其中对齐的全零基础机器字是 `nop`，不是空洞或停机。向后定位的实际游戏错误行为待核实，项目工具应拒绝覆盖已有输出。

## 7. include 与导出

本地手册 **ASM** 给出：

```asm
include ../std_lib
jmp std_lib.print
```

被引入文件使用：

```asm
pub print:
...
```

含义是把被包含文件装配结果插在 include 当前位置；它不是 C 头文件只包含声明，也不是链接器外部符号。`pub` 导出标签或常量，通过文件名加点访问。路径例子省略 `.asm` 后缀。

include 的重复包含、环、路径查找、嵌套命名空间具体处理未在已读手册中详列。第一版编译输出可使用单个自包含 `.asm` 避免依赖这些边界，但本规格保留游戏功能的存在。

## 8. 别名及准确展开

别名由当前 `spec.isa` 位串定义，不是执行器新 opcode，也不应被当作不可分割的一次硬件执行。

### 8.1 单机器字别名

```asm
mov d, b       ; or  d, zr, b
neg d, b       ; sub d, zr, b
not d, b       ; nor d, zr, b
```

寄存器与 U16/标签两种形式均存在，各 4 字节。32 位按位取反不会仅限于低 16 位。例如 `not r1, 0` 的值是 `0xffffffff`。

### 8.2 栈

```asm
push r1
; 8 字节，依次执行：
sub sp, sp, 4
store_32 [sp], r1

pop r1
; 8 字节，依次执行：
load_32 r1, [sp]
add sp, sp, 4
```

栈向低地址增长，每项 4 字节，`sp` 指向栈顶已使用的项。没有 push 立即数定义，先装入寄存器再 push。没有栈空检测或自动分配内存。

特殊参数必须尊重逐条展开：`push sp` 存的是执行 `sub` **之后**的 sp；`pop sp` 是先从旧 sp 加载到 sp，再对**新加载的 sp**加 4。不能为了模拟一般 push/pop 而把这两种情况悄悄改成别的语义。常规 ABI 应避免它们。

### 8.3 call

```asm
call function
; 20 字节，依次执行：
counter flags
add flags, flags, 20
sub sp, sp, 4
store_32 [sp], flags
jmp function
```

若 call 从地址 C 开始，返回地址为 `u32(C+20)`。返回地址从 PC 推导，**不是 C+4**。在 callee 入口，栈顶存放这个大端 32 位地址，sp 比调用前少 4。

`flags` 被替换为返回地址；并不保存调用前比较结果。`call` 不传递参数、不保存任何通用寄存器、不建立栈帧、不分配局部变量，也不会自动调用 `main`。

### 8.4 ret

```asm
ret
; 12 字节，依次执行：
load_32 flags, [sp]
add sp, sp, 4
jmp flags
```

返回后 flags 仍含返回地址，而非先前的 E/U/S 比较值。只有配对的栈内容与 sp 布局正确时 ret 才能回到调用处；顶层入口不应执行一个没有返回地址的 ret。

### 8.5 字节计数例子

```asm
mov sp, 4096     ; PC 0，4 字节
call f          ; PC 4，20 字节，返回地址 24
stop:           ; 地址 24
jmp stop        ; PC 24，4 字节
f:              ; 地址 28
ret             ; PC 28，12 字节
```

映像总长 40 字节。`call` 后 callee 的 sp=4092，`M[4092..4095]=00 00 00 18`，flags=24；`ret` 后 sp=4096、PC=24、flags=24。

## 9. ISA 定义语言的处理

游戏汇编器按指令定义列表寻找第一个匹配语法，而不是根据英文助记符猜编码（**ISA-LANG**）。编写兼容汇编器时必须保留定义优先级。

- 字段定义中的每项是位串；寄存器字段每项 4 位。
- `%name(fields)` 指定操作数可接受字段；`|` 表示可选字段类型的并集。
- 机器码中的字母引用操作数名的首字母，不能把 `%dest` 按“第几个参数”错误绑定。
- 位串中的固定位 0/1 必须原样输出；重复出现的字母按给定位宽从高到低填入。
- 当前 ISA 不使用 `[patterns]`、虚拟操作数、断言或位切片，但游戏定义语言支持它们。
- `$start/$end` 是汇编时的当前指令起止偏移，不是硬件寄存器。
- 手册中的表达式 `+ - * / /u % << >>` 等作用于汇编计算；它们存在不等于 CPU 自动支持对应指令。
- 多机器字别名的位串必须完整计数：本快照 72 种 4 字节形式、2 种 8 字节形式、1 种 12 字节形式、1 种 20 字节形式，共 76 种。

手册提到 RAM 组件自身也可反转端序；ISA 的 `endianness` 与端口配置是两个层次。目标硬件已确认保持标准，因此后续工具链统一采用标准大端，不靠切换汇编器设置来补救错误的数据布局。
