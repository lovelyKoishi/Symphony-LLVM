# Symphony 架构与硬件行为

## 1. 范围和记号

目标为 Turing Complete 的 Symphony 架构，含 `mul/div/mod` 扩展。

- `u32(x) = x mod 2^32`；寄存器保存 32 位位串。
- `s32(x)` 将相同位串解释为二进制补码有符号数。
- `R[n]` 是寄存器，`PC` 是独立的程序计数器，`M` 是主内存，`P` 是持久内存。
- `A/B/D` 表示机器指令的字段，不保证与汇编操作数变量的字母相同。
- 所有本节定义中的源操作数，除明确列出的多指令别名外，都在本条基础指令写回前读取。

## 2. 机器状态与寄存器

| 编号 | 汇编名 | 行为 |
| --- | --- | --- |
| 0 | `zr` | 恒为 0，写入不会留下可见结果 |
| 1–13 | `r1`–`r13` | 13 个通用 32 位寄存器 |
| 14 | `sp` | 普通可读写 32 位寄存器；栈别名使用它 |
| 15 | `flags` | 普通可读写 32 位寄存器；比较与条件跳转按约定使用它 |
| 独立状态 | `PC` | 32 位字节地址，不属于上述 16 个寄存器 |
| 独立状态 | 时间快照 | `time_0` 缓存的 64 位时间，供 `time_1` 读取高半部 |

ISA 没有名为 `r0/r14/r15` 的字段值。使用 `zr/sp/flags`；手册中的其他架构示例 `r0` 不自动成为这里的合法名称。

标准参考模型把寄存器与 PC 初始设为 0，时间快照也为 0；主内存装入汇编结果。程序映像之外的主内存在启动时为 0；零初始化的静态对象可直接使用该区域，无需在文件末尾写入零或增加启动清零循环。此约定不适用于持久内存。C 的启动代码仍应显式选择并初始化栈与运行时所需状态。

`flags` 并不是 x86 的 EFLAGS。`add/sub/mul/div/mod`、逻辑运算、移位、load 等通常只写指定目的寄存器，不隐式更新 `flags`。若目的就是 `flags`，当然会覆盖它。`call/ret` 别名也明确覆盖 `flags`。

## 3. 基础指令编码、取指和 PC

每条基础机器指令固定 **4 字节**。默认按大端装入主内存；位串和数值字的关系为：

```text
bit 31   30:29  28  27:24  23:20  19:16  15:12  11:8  7:0
    0      M    I    O       D      A       0      B     0     寄存器形式
    0      M    I    O       D      A        immediate[15:0]    立即数形式
```

```text
mode      = (word >> 29) & 3
immediate = (word >> 28) & 1
opcode    = (word >> 24) & 15
D         = (word >> 20) & 15
A         = (word >> 16) & 15
B         = (word >> 8)  & 15
A_value   = R[A]
B_value   = immediate ? (word & 65535) : R[B]
```

| M | 类别 | 首字节范围（合法形式的范围包络） |
| --- | --- | --- |
| 0 | I/O | `00..1F` |
| 1 | ALU | `20..3F` |
| 2 | Jump | `40..5F` |
| 3 | Memory | `60..7F` |

范围包络不等于其中每个 opcode 均有定义。当前合法位串见 [ISA 定义](../isa/spec.isa)。位 31、寄存器形式的空位等由汇编器生成零，不定义修改保留位后的兼容性。

基础指令正常完成后 `PC = u32(old_PC + 4)`；跳转成立则 `PC = B_value`，不是 `PC+4+B_value`，没有分支延迟槽。`counter d` 读取本条指令的地址 `old_PC`，而不是下一条地址。来源：**PC/REF**。

`PC` 是字节偏移，不是源码行号或指令序号。源码的一条 `call` 包含五条基础指令；数据与填充也占用字节。

## 4. ALU

下表中的 `a/b` 表示已读取的源值，结果写入目的寄存器并保留低 32 位。

| opcode | 汇编名 | 结果 |
| --- | --- | --- |
| 0 / `0x0` | `nand d, a, b` | `~(a & b)` |
| 1 / `0x1` | `or d, a, b` | `a \| b` |
| 2 / `0x2` | `and d, a, b` | `a & b` |
| 3 / `0x3` | `nor d, a, b` | `~(a \| b)` |
| 4 / `0x4` | `add d, a, b` | `a + b`，按 32 位回绕 |
| 5 / `0x5` | `sub d, a, b` | `a - b`，按 32 位回绕 |
| 6 / `0x6` | `xor d, a, b` | `a ^ b` |
| 7 / `0x7` | `lsl d, a, b` | 逻辑左移，低位补零 |
| 8 / `0x8` | `lsr d, a, b` | 逻辑右移，高位补零 |
| 9 / `0x9` | `asr d, a, b` | 算术右移，复制原 bit 31 |
| 10 / `0xA` | `cmp a, b` | 比较结果写入 `flags`，见下一节 |
| 11 / `0xB` | 未定义 | 不生成，不自行解释成其他操作 |
| 12 / `0xC` | `mul d, a, b` | `u32(u32(a) * u32(b))`，没有乘积高半部目的寄存器 |
| 13 / `0xD` | `div d, a, b` | 无符号商 `floor(u32(a)/u32(b))`，`b != 0` |
| 14 / `0xE` | `mod d, a, b` | 无符号余数，`b != 0` |
| 15 / `0xF` | 未定义 | 不生成 |

这些指令均有寄存器 B 和 U16 立即数 B 两种形式（`cmp` 为两操作数语法）。立即数零扩展，不是符号扩展。例如 `div r3, r1, 65535` 的除数是正的 65535。

新增指令的首字节分别为：`mul=2C/3C`、`div=2D/3D`、`mod=2E/3E`，前者是寄存器形式，后者是立即数形式。除法与取余为无符号运算。低 32 位乘积对于有符号与无符号输入的位串结果相同，但这不意味着有符号除法也可直接使用 `div`。

移位量的有效范围为 `0..31`。参考执行器遇到越界移位、除零或取余零时会报错。

C 的有符号除法需要符号处理并向零截断，余数符号跟随被除数。例如 C 的 `-7/3=-2`、`-7%3=-1`，不能把 `0xfffffff9` 直接送入硬件无符号除法取得该结果。

## 5. 比较位与跳转

`cmp a, b` 计算三个彼此独立的布尔值，打包到 `flags`，高 29 位为 0：

```text
E = (u32(a) == u32(b))
U = (u32(a) <  u32(b))
S = (s32(a) <  s32(b))
flags = (S << 2) | (U << 1) | E
```

| bit | 名称 | 含义 |
| --- | --- | --- |
| 0 | E | 相等 |
| 1 | U | 无符号小于 |
| 2 | S | 有符号小于 |

例如 `cmp 0xffffffff, 1` 的抽象结果是 `flags=4`：有符号 -1 小于 1，无符号 4294967295 大于 1。该例是语义表达，不是合法的两立即数 `cmp` 汇编。

条件电路依据 opcode `c` 和源 flags 值 `f`：

```text
matched = ((c & (f & 7)) != 0)
taken   = matched XOR ((c & 8) != 0)
```

所有当前跳转的 A 字段都指定 `flags`，D 字段为零；没有隐式重新比较。

| 汇编 | 条件 opcode | 条件 | 当前文本支持的目的地 |
| --- | --- | --- | --- |
| `jmp` | 8 | 恒真，不依赖 flags 内容 | 寄存器，或 U16 立即数/标签 |
| `je` | 1 | E | U16 立即数/标签 |
| `jne` | 9 | 非 E | U16 立即数/标签 |
| `jb` | 2 | U | U16 立即数/标签 |
| `jae` | 10 | 非 U | U16 立即数/标签 |
| `jbe` | 3 | E 或 U | U16 立即数/标签 |
| `ja` | 11 | 非（E 或 U） | U16 立即数/标签 |
| `jl` | 4 | S | U16 立即数/标签 |
| `jge` | 12 | 非 S | U16 立即数/标签 |
| `jle` | 5 | E 或 S | U16 立即数/标签 |
| `jg` | 13 | 非（E 或 S） | U16 立即数/标签 |

`jmp` 使用 c=8，因此 `matched=false`，再异或 true 得到恒真。不要把它实现为“flags 必须满足某个比较”。

不能在 `cmp` 和使用其结果的条件跳转之间放置 `call/ret` 或任何覆盖 `flags` 的指令。普通 `mov r1, 0` 不会改 flags。

## 6. 主内存与持久内存

### 6.1 地址、容量和端序

标准参考 **REF** 的主内存是 `1<<24` 字节（16 MiB），物理字节索引为 `u32(address) & 0x00ffffff`。地址寄存器和 PC 仍为 32 位；不能将它们缩成 24 位，更不能因为立即数只有 16 位就缩成 16 位。

主内存同时用于取指、数据、栈和屏幕缓冲区。`load/store` 可读写程序字节，不存在文档规定的代码写保护。屏幕连接同一个 Main Memory。栈区与帧缓冲区的划分属于软件内存布局，不是硬件固定地址。

**主内存多字节访问采用大端**：

```text
store_32 [address], value = 0x12345678
M[address+0] = 0x12
M[address+1] = 0x34
M[address+2] = 0x56
M[address+3] = 0x78
```

`load_16` 读取 `0x1234`，`load_8` 读取 `0x12`。不能用同一个地址读 byte 来表示取 32 位值的低 8 位；低字节在 `address+3`。

标准 **REF** 的主内存 load/store 按每个字节分别屏蔽地址，包括跨 `0xffffff → 0` 的访问。非对齐 load/store 也按连续字节组合，未定义必须对齐的异常。后续 C ABI 可以为效率要求自然对齐，但不能把 ABI 要求说成硬件强制。

### 6.2 操作表

| 内存 opcode | 指令 | 行为 |
| --- | --- | --- |
| 0 | `load_8 d, [b]` | 从主内存读 1 字节，零扩展为 32 位 |
| 1 | `load_16 d, [b]` | 从主内存读 2 字节，大端，零扩展为 32 位 |
| 2 | `load_32 d, [b]` | 从主内存读 4 字节，大端 |
| 3 | `pload d, [b]` | 从持久内存读 4 字节，大端 |
| 4 | `store_8 [b], a` | 把 a 的低 8 位写入主内存 |
| 5 | `store_16 [b], a` | 把 a 的低 16 位大端写入主内存 |
| 6 | `store_32 [b], a` | 把 a 的全部 32 位大端写入主内存 |
| 7 | `pstore [b], a` | 把 a 的全部 32 位大端写入持久内存 |

`b` 是地址，可为寄存器或 U16 数字。当前 ISA 的内存立即数形式只标注 `(immediate)`，没有 `(label)`；用标签地址时先 `mov` 到寄存器。当前没有 `[base+offset]`、后自增或隐式缩放寻址。需要先显式地址运算。

`load_16/load_32` 的 ISA 中文注释误写“读取 8 位”；机器编码、正式关卡说明 **RAM**、参考执行模型 **REF** 一致定义它们为 16/32 位，应以实际宽度为准。

`load_8`/`load_16` 不做符号扩展。加载 C 的 signed char/short 后，编译器须另外扩展符号。

### 6.3 持久内存与端口顺序

持久内存与主内存是分离的地址空间，在重启之间保留值（**SSD**）。不能用 `load_32` 访问持久内存，不能把 `pstore` 当普通全局变量 store。

**REF** 的 `MAX_SSD=1000` 只是该关卡测试数组的范围，不能据此断言持久内存硬件只有 1000 字节。该测试写入保护还有 `< MAX_SSD - 4` 的限制，不作为目标硬件边界规则。容量、越界读写以及文件持久化时机仍须核实。

游戏内存端口按从上到下的顺序作用，同一地址的读写先后受端口位置影响（**RAM**）。标准设计中取指及 load 端口在 store 端口之前。基础指令语义为先取到当前机器字，再完成该指令的 store；写到自己的机器字不会倒过来改变正在执行的指令。更细的组合电路延迟不属于本阶段软件执行器的精度目标。

## 7. I/O 指令

| I/O opcode | 指令 | 行为及状态变化 |
| --- | --- | --- |
| 0 | `nop` | 不写寄存器/设备，PC 正常前进；不是停机 |
| 1 | `in d` | 读取当前输入端口的 32 位值到 d |
| 2 | `out b` | 使能输出，输出寄存器值或 U16 数字 |
| 3 | `keyboard d` | 从键盘读取下一事件，没有事件为 0 |
| 4 | `screen a, b` | a 的值为设置索引，b 为设置值；a 必须是寄存器，b 可为寄存器或 U16 |
| 5 | `time_0 d` | 读取当前 64 位 Unix 纳秒时间，缓存完整快照，把低 32 位写到 d |
| 6 | `time_1 d` | 把上一次快照高 32 位写到 d，不重新读当前时间 |
| 7 | `counter d` | 把本条指令 PC 写到 d |

`in` 是输入引脚，不是键盘事件队列。`out` 是硬件输出事件，不自动打印 ASCII 字符，也不等于写屏幕。

`time_1` 在首次 `time_0` 之前读到 0；两次 `time_0` 会使第二次快照替换第一次。读 64 位时间应按 `time_0 low` 再 `time_1 high` 的顺序，不能先读高位再读低位。来源：**IO/REF**。

## 8. 显示屏

屏幕读取关联 RAM 的字节；`screen` 只改设备设置，不复制或清空帧缓冲区。若用字符串地址做缓冲区，零字节仍是一个字符单元，不是硬件停止显示的字符串结束符。

| 模式值 | 模式 | 单元布局 | 设置索引 |
| --- | --- | --- | --- |
| 0 | ASCII 8 | 每字节一个字符，96 列 × 40 行 | 0 模式、1 起始字节偏移、2 前景、3 背景、4 字体 |
| 1 | ASCII 32 | 每单元 4 字节：字符、前景、背景、填充 | 0 模式、1 起始偏移 |
| 2 | Pixel 8 | 每像素 1 字节：RRRGGGBB | 0 模式、1 起始偏移、2 分辨率 |
| 3 | Pixel 32 | 每像素 4 字节：R、G、B、填充 | 0 模式、1 起始偏移、2 分辨率 |

ASCII 8 的颜色寄存器使用 `0xRRGGBB`，白色为 `0x00ffffff`；单元内的 8 位颜色则为 RRRGGGBB。Pixel 32 的 RGB 字节与填充字节按内存地址顺序解释；大端 `store_32` 的红色像素示例是 `0xff000000`，不是 `0x00ff0000`。

像素模式分辨率参数 n：`width=4*(n+1)`、`height=3*(n+1)`。手册给定范围从 4×3 到 1024×768，对应 n=0..255；越界 n 的设备行为待验证。参数 31 得到 128×96。

ASCII 8 framebuffer 为 `offset + y*96 + x`，占用 3840 字节；ASCII 32 同样坐标的单元地址是 `offset + 4*(y*96+x)`，占用 15360 字节。字体名称包括 cp437/cp850/cp910/cp866，数值与具体字体的完整映射在现有文字材料中未给出，不凭列举顺序猜测。

设置索引 2 随模式改变含义：ASCII 8 是前景色，Pixel 模式是分辨率。参考编译器的 `screen_foreground` 与 `screen_resolution` 都映射 2，由此不能推断冲突或新增寄存器。

## 9. 键盘

Localized 模式下，**回车键码为 10，退格（BS）键码为 13**。因此按下事件分别是 `0x10a` 与 `0x10d`，不是按常见 PC ASCII 习惯把退格写成 8、回车写成 13。

每次按键产生按下和松开两个事件。标准参考中事件格式是：低 8 位键码，bit 8 为是否按下；其余位不用于该格式。例如 `0x101` 是按下码 1，`0x001` 是松开码 1。无事件为 0，每次 `keyboard` 读取一项。

- 本地化模式尽量按字符映射，如 `w → 0x77`。
- 物理位置模式按行/列各 4 位编码，空格示例为 `0x53`。
- Localized 模式方向键为 Up=1、Right=2、Down=3、Left=4，与 **REF** 的 Up/Right/Down 一致；物理位置模式仍遵循另一套位置编码。
- 队列容量、重复按键策略、焦点行为以及切换模式时队列处理未由当前文本材料完全确定。

## 10. 未定义与未验证项

当前没有 `halt`、硬件异常入口、系统调用、浮点、原子操作、中断、硬件 signed-div、carry 指令或乘积高半部指令的 ISA 定义。不要把游戏可放置的 Halt 组件视为已存在的 `halt` 指令。

`jmp self` 是运行中的无限循环，不是硬件停机。CPU 也不会识别 `main`、`return 0` 或程序文件结束。

除零、取余零、移位 >=32、未定义 opcode、保留位变体、持久内存边界、非法屏幕参数、失去有效取指地址后的行为都不能由 ISA 表格自行补出。后续执行器对这些情况的诊断与硬件真实输出必须分别标记。
