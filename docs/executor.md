# 汇编执行器规定

## 1. 目标和事实边界

“汇编执行器”在本项目中指将汇编装配为字节、再按 Symphony 机器指令执行的软件工具。汇编器负责语法和布局，CPU 核心负责机器语义。它用于验证未来 LLVM 输出；**本页是第一阶段的目标契约；当前实现已提供机器字执行与编码验证子集，完整实现范围见 [backend.md](backend.md)。**

硬件行为以 [architecture.md](architecture.md) 为准。下面还规定执行器自身的错误处理、可重复运行与调试接口；这些项目规定不代表游戏硬件提供相同异常或停机机制。

执行器必须执行装配后的**实际机器字**，不能只解释源码行。这是发现指令长度、跳转地址、端序、数据误执行、自修改代码和别名展开错误的必要条件。

## 2. 分层

```text
源 .asm + ISA 定义
        ↓ 汇编、符号解析、别名展开、布局检查
程序字节 + 符号表 + 源码到机器地址映射
        ↓ 装载到主内存
机器核心：PC → 取 4 字节 → 解码 → 执行 → 提交
        ↕
可注入的输入、键盘、时间、屏幕、持久内存设备
        ↓
运行结果、指令轨迹、输出事件、诊断
```

第一版可以仅实现当前 ISA 所需的定义语言子集，但必须明确列出不支持的 `[patterns]`、虚拟操作数等，而不是忽略它们后继续装配。对用户给定新 ISA，应在装配前校验支持范围。

## 3. 必须保存的状态

| 状态 | 要求 |
| --- | --- |
| 寄存器 | 16×32 位；所有写回截为 32 位，`zr` 始终读 0 |
| PC | 32 位独立值，不用指令列表下标替代 |
| 主内存 | 标准 16 MiB 字节数组，读写的每字节索引屏蔽低 24 位 |
| 持久内存 | 独立字节空间，容量及越界政策显式配置；不能拿测试 1000 字节冒充硬件容量 |
| 时间快照 | 64 位，初值 0 |
| I/O 输入 | 可按基础指令步数或输入读取事件提供值的供应器；运行记录说明所用方式 |
| 键盘 | 独立事件队列，读取时消费一项，无事件返回 0 |
| 屏幕 | 模式、偏移、模式相关设置及关联主内存；必要时从内存导出画面 |
| 输出 | 带 PC、步数、值的输出事件日志 |
| 调试状态 | 断点、执行步数、源码映射、终止原因；这些不是 guest 寄存器 |

用户确认程序映像之外的主内存在启动时为 0。执行器先建立全零主内存，再把程序字节拷入指定装载地址。默认约定装载到 0，PC=0，寄存器=0；其他装载地址必须使标签重定位和入口一致，不能只移动字节不更新绝对跳转。

不自动执行 `jmp main`、初始化 sp 为 65535 或插入隐藏的返回地址。需要 C 启动运行时的测试应显式包含相应指令。

## 4. 单步执行与提交

一个 `step` 执行**一条 4 字节基础机器指令**：

1. 保存 `old_PC`；从主内存取 `[PC..PC+3]`，大端组合为 32 位机器字。
2. 校验当前合法编码和执行策略；解码 mode、opcode、I、D、A、B/imm16。
3. 读取本条所有源寄存器。地址与 store 数据都来自写回前状态。
4. 计算目的值、内存写入、设备效果和 `next_PC`。
5. 按机器语义提交结果，将寄存器结果截为 32 位，保证 zr 为 0，设置 PC。
6. 增加基础指令计数，记录对应轨迹与事件。

关键细节：

- `counter r1` 返回 old_PC。
- 条件跳转失败 `next_PC=u32(old_PC+4)`；成功用绝对目标。
- `load_32 r1, [r1]` 从旧 r1 指向的地址读取，再覆盖 r1。
- `store_32 [r1], r1` 同一旧 r1 同时作地址与值。
- store 当前代码后，后续取指重新读内存，不能长期缓存源行或原始指令列表。
- 主内存访问包括跨末尾的每个字节回绕，PC 本身仍按 32 位更新。
- 机器字本来就没有“这是数据”的标记；CPU 核心不能依据源码数据标签自动跳过它。

若严格模式在当前基础指令提交前报错，保留 old_PC 和该条指令之前的 guest 状态。多机器字别名不能整体回滚：如果 call 的前几条已经完成，之后错误时应保留这些已完成的机器指令效果。

## 5. 解码与别名

核心只需标准基础 opcode，加上新增 ALU 12/13/14。`mov/neg/not` 与底层 `or/sub/nor` 编码相同；反汇编可用任一种展示，但机器语义只能有一个。

`push/pop` 必须分别执行两步，`call` 五步，`ret` 三步。源码级“步过”可以作为调试功能，但内部轨迹和时间/输入采样仍遵守基础步数。

例如在 C=4 的 call：

| 基础步 | 当前 PC | 效果 |
| --- | --- | --- |
| 1 | 4 | `counter flags`，flags=4 |
| 2 | 8 | `add flags, flags, 20`，flags=24 |
| 3 | 12 | `sub sp, sp, 4` |
| 4 | 16 | `store_32 [sp], flags` |
| 5 | 20 | `jmp function` |

不能把五步计为一步后仍声称与硬件的计数器、输入或时间事件一致。

当前合法汇编没有覆盖所有硬件可能解码的位型。严格执行器应对未定义 opcode 和保留位非规范的机器字报 `UnsupportedEncoding`，并明确说明这是诊断政策。不能声称实际电路也会抛异常。未来如增加宽松硬件模式，须另给非规范编码的硬件证据。

## 6. 算术边界政策

| 情形 | 硬件证据 | 第一版严格执行器要求 |
| --- | --- | --- |
| add/sub/mul 超过 32 位 | 已有位宽语义 | 保留低 32 位，不因宿主整数无限精度改变结果 |
| 有效 unsigned div/mod | 用户确认 | 用 u32 商/余数计算 |
| div/mod 除数 0 | 未核实 | 提交前停止，报告 `UnverifiedBehavior: division-by-zero`，不制造数值 |
| lsl/lsr/asr 位移 0..31 | 标准测试 | 按对应 32 位逻辑/算术语义 |
| 位移 >=32 | 标准测试未覆盖 | 报 `UnverifiedBehavior: shift-count`，不偷偷 `&31` |
| 非对齐数据访问 | REF 按字节组合 | 允许按连续字节访问 |
| 非对齐取指 | REF 算法可从任意地址取字；专项硬件测试缺失 | 可提供验证用警告；不宣称硬件必定对齐陷阱 |
| 主内存跨边界 | REF 每字节掩码 | 按 24 位物理字节索引回绕 |
| 持久内存越界 | 容量/边界未核实 | 按显式设备范围给诊断，禁止沿用主内存掩码 |

有符号行为不能依赖宿主语言默认：例如 Python 的 `-7 // 3` 是 -3，而 C 有符号向零截断为 -2。硬件 div/mod 核心只处理无符号位串；有符号展开由 guest 指令完成。`asr` 必须先把 a 解释为 s32 再右移，并把结果转回 u32。

## 7. 设备与可重复性

### 输入与输出

`in` 从输入供应器读值，不消费键盘队列。默认供应器可以固定 0，但必须标识为测试环境选择，而非硬件在所有关卡上的事实。

`out` 生成一个输出事件。UI 可以附加十进制、十六进制或字符展示，原始数值必须保留，不把所有值强制转成字符。未执行 out 时，不能把某个旧输出端口值再次记录成新输出。

### 时间

默认使用可注入、可重放的 64 位纳秒供应器。测试设置 `T=0x1122334455667788` 时：

```text
time_1 → 0                  （还没有快照）
time_0 → 0x55667788          （同时保存 T）
将当前时间供应值更改为 T2
time_1 → 0x11223344          （仍是旧快照高半部）
```

实时运行可以连接宿主时钟，但须与确定性测试模式分开。`time_1` 不能再查询供应器。

### 键盘与屏幕

队列事件按次序被 `keyboard` 消费；空队列返回 0。输入模式与键码由测试或设备配置说明。

screen 设置索引来自寄存器的**值**。`screen r2, 3` 中若 r2=1，则修改 framebuffer 偏移为 3，不是修改“寄存器编号 2 对应的屏幕设置”。

屏幕从关联主内存读取单元。渲染器不以 NUL 结束、不把 ASCII 32 颜色误当 24 位颜色、不把 Pixel 32 末尾填充字节当 alpha。非法模式/设置索引/分辨率须诊断为设备范围未定义或无效，不无声映射成另一模式。

### 重置与持久化

区分机器 reset、重载程序、清除持久内存三种动作。持久内存保留或写入镜像必须显式；普通 reset 不自动清空 P。C 的 `.bss` 清零属于启动程序或装载协议，不能由 CPU 核心针对变量名自动完成。

## 8. 终止、限制和诊断

没有原生 halt opcode。执行器宿主可以因以下原因停止，并给出不同状态：

- 指定断点或外部停止请求。
- 达到基础指令步数预算。
- 达到测试约定的成功/失败输出条件。
- 不支持的编码、未验证的边界行为、装载或设备配置错误。

`jmp self` 仍是一次成功执行的跳转，可以在调试层提示稳定自循环，但不得默认认定“程序成功”。代码区域结束不能自动表示 ret 或 exit。取到零填充时是 nop，最终可能走到其他内存，步数预算必须有默认值。

诊断至少包含：阶段（汇编/装载/执行）、错误类别、当前 PC、机器字、源码文件/行号（有映射时）、相关寄存器与地址、已完成基础步数、最近轨迹。错误时不得把尚未完成的 out 或写内存作为已发生事件报告。

项目汇编器的严格规则：未定义/重复符号、未知寄存器、没有匹配的操作数形式、U16 超范围、向后 `@`、映像超容量、include 环、不支持的 ISA 定义功能都应明确报错；不要因 game 版本可能宽松就静默截断或忽略。

## 9. 运行记录与溯源

每次用于验证编译器的运行至少记录：ISA hash、映像 hash、入口与装载地址、设备和主存配置、执行模式、输入/键盘/时间脚本、持久内存初值来源、步数预算和终止原因。

完整 trace 可按需打开，每条包含 old_PC、原始 4 字节/机器字、解码、寄存器与内存变化、next_PC、设备事件。源码映射须允许一行汇编对应多条基础指令，也允许数据/填充不对应普通指令。

## 10. 验收用例清单（均待实现后运行）

以下是预期向量，不是本阶段已经取得的运行结果。

| 用例 | 预期 |
| --- | --- |
| `mov r1, 0x1234` | 字节 `31 10 12 34`，结果 r1=4660 |
| `mul r3,r1,r2` | 字节 `2C 31 02 00` |
| `div r3,r1,3` | 字节 `3D 31 00 03` |
| `mod r3,r1,r2` | 字节 `2E 31 02 00` |
| `U8 1; @8; U8 2`（各自一行） | 映像长 9，第 0 字节 1，第 8 字节 2 |
| 独立 `next:` 标签示例 | 标签是展开后字节位置；前向引用成功 |
| `store_32` 值 `0x12345678` | 连续字节 `12 34 56 78`；load_8 首字节为 0x12 |
| `load_8` 读 0xff | 寄存器为 255，不是 -1 位串 |
| 非对齐/跨末尾 load/store | 符合每字节大端组合及 24 位回绕 |
| `add 0xffffffff,1`、`sub 0,1` | 0、0xffffffff |
| `mul 0xffffffff,2` | 0xfffffffe |
| `div 0xffffffff,2`、`mod 0xffffffff,2` | 0x7fffffff、1 |
| `cmp 0xffffffff,1` | flags=4；jl 成立、jb 不成立 |
| `cmp 0x80000000,0x7fffffff` | flags=4 |
| E/U/S 与所有 16 个条件值的组合 | 条件组件 8×16 真值表符合公式；具名分支符合选定 opcode |
| 普通 ALU 目的不是 flags | flags 保持不变 |
| 写 zr | 读取仍为 0 |
| call/ret 示例，SP=4096 | [assembly.md](assembly.md) 中 40 字节布局及 PC/SP/flags 轨迹完全一致 |
| 嵌套 call 与递归 | 返回地址栈后进先出，SP 恢复，callee 约定由 guest 正确实现 |
| push sp / pop sp | 严格按各自两条基础指令的中间状态执行 |
| counter | 返回该基础指令地址而非下一条 |
| time 快照 | time_1 使用缓存；首次读取为 0 |
| keyboard 队列 | 按下/松开分离，读取消费，空队列返回 0 |
| out | 数值原样记事件，与屏幕和键盘分离 |
| screen mode/offset | 由寄存器值选设置；改主存后画面随之变化 |
| 程序写后续指令再跳转 | 执行修改后的主存机器字，不是旧源码缓存 |
| div0/移位32/未知opcode | 明确未验证/不支持诊断，保留已提交前缀 |
| self-loop/落入零填充 | 不自动成功退出，受步数限制停止 |

硬件差分验收时应先在游戏中观测同样输入，再与软件执行器比较寄存器、主存、PC 和 I/O；不得仅让两个共享同一错误假设的软件实现相互“验证”。
