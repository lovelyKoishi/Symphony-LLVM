# 通用后端优化与基准

第一轮（全函数寄存器分配）比较的是上一版已完成指令选择优化的后端，与本轮全函数寄存器分配后的后端。它不是最初甜甜圈优化前的基线，也没有改变前端优化等级。两边都是 `-O1`、相同 C 源码和 seed=123。

## 改动

- 全函数 CFG 活跃分析：PHI 的 incoming 在前驱边上使用，按固定点计算 live-in/live-out，再构建干涉图并分配 r7..r11。参数、跨块值和循环值均可分配；溢出选择按循环深度和使用次数加权。
- 保持 caller-clobbered ABI：跨真实函数调用存活的值保留栈槽，处理递归与间接调用。设备接口及内联 intrinsic 不会无故导致寄存器溢出。尚未实现 callee-saved 分配和调用点拆分溢出。
- PHI 并行复制按物理位置排序，跳过同位置复制；仅循环依赖使用暂存槽，处理寄存器交换、栈溢出值与多前驱边。
- 省略没有局部栈需求、真实调用或已用栈实参的叶子函数栈帧；删除未用参数及融合比较的无效栈槽。保留其他函数的 frame pointer、调用对齐和栈实参布局。
- 新增七类通用基准和可选执行器统计，并加入 CTest。它们是小型固定工作负载，用于判断优化是否只对某个演示有效；不代表所有应用都会达到同样收益。

## 执行指令数

所有工作负载都先在主机 C 编译器上运行，开启 UBSan，取得参考校验值；再编译为真实目标机器字并在参考执行器中运行。I/O 负载还逐项验证 64 次设备输出；各例检查退出值、SP 和 r13 恢复。

| 负载 | 优化前 | 优化后 | 减少 |
| --- | ---: | ---: | ---: |
| 整数算术 | 9,254 | 4,895 | 47.1% |
| 分支与循环 | 21,230 | 9,230 | 56.5% |
| 数组遍历 | 24,732 | 10,464 | 57.7% |
| 函数调用 | 7,206 | 3,878 | 46.2% |
| 递归 | 17,015 | 14,460 | 15.0% |
| 字符串与 libc | 315,247 | 175,663 | 44.3% |
| 设备输出 | 2,597 | 801 | 69.2% |

## 数据访存、代码与栈

访存次数只统计执行的 load/store，包括函数栈和持久内存指令，排除取指；设备 out 不算 RAM 访存。代码大小按展开后的基础机器字计算，排除全局数据和地址填零间隙。最大栈占用包含返回地址、frame pointer 和局部空间；执行器在 SP 首次到达指定 stack-top 后开始跟踪，以排除装载栈顶常数过程的中间值。

| 负载 | 数据访存（前→后） | 代码字节（前→后） | 最大栈字节（前→后） |
| --- | ---: | ---: | ---: |
| 整数算术 | 2,313 → 6 | 340 → 216 | 48 → 12 |
| 分支与循环 | 6,666 → 808 | 672 → 368 | 96 → 24 |
| 数组遍历 | 9,514 → 1,674 | 764 → 468 | 376 → 280 |
| 函数调用 | 2,441 → 776 | 420 → 292 | 64 → 28 |
| 递归 | 4,893 → 3,499 | 468 → 424 | 504 → 216 |
| 字符串与 libc | 102,444 → 15,595 | 4732 → 3224 | 360 → 172 |
| 设备输出 | 968 → 6 | 352 → 196 | 56 → 12 |

JSON 记录源码哈希、后端二进制哈希、前端等级、参考校验值及完整统计：[优化前](../benchmarks/results/before.json)、[优化后](../benchmarks/results/after.json)。这是软件参考执行器的统计，不是实机时间测量；本轮没有给出实机加速倍数。

## 复现

```bash
cmake --build build
python3 tools/benchmark.py --output build/bench.json
python3 tools/benchmark.py --output build/bench.json --compare benchmarks/results/before.json
ctest --test-dir build -LE slow --output-on-failure
```

也可以对任意已有汇编采样：

```bash
python3 tools/symphony_machine.py build/program.asm --run --profile --max-steps 5000000
# 低地址布局需指定实际栈顶
python3 tools/symphony_machine.py build/program.asm --run --profile --stack-top 0x10000
```

达到 max-steps 的结果属于执行片段，不能当成完整程序的统计。profile 默认关闭。比较脚本要求相同等级、seed、源码哈希和结果；保存 JSON 方便后续优化继续对照。

## 验证与边界

除已有整数位宽、符号处理、结构体、GEP、调用、TTY、图形和 libc 回归，还增加六值 PHI 轮换及寄存器溢出、循环中条件间接调用、无帧叶子函数对父帧的保护，以及统计器不计取指/正确记录跳转和栈深的测试。甜甜圈的普通、静态和低地址诊断测试也全部通过上游差分。

本轮没有改 C 数据布局、寄存器 ABI、设备协议或默认前端优化等级。尚未实现 callee-saved 寄存器、调用点活跃区间拆分、完整循环地址强度削减和通用窥孔优化，仍有后续空间。

## 第二轮：调用点保存与批量内存

这一轮以第一轮完成的编译器和原字节循环 libc 为基线；与前面表格的起点不同。保留 r7..r11 caller-clobbered ABI，高收益值跨调用时仍分配寄存器，仅在真实调用前保存、返回后恢复。调用成本按循环深度加权，低收益值继续放栈；同一函数内不同调用复用每个物理寄存器的保存槽。恢复不覆盖 r1 返回值，间接调用的 r11、超六实参、递归和嵌套调用均保持原约定。

libc memcpy/memset 增加对齐 32 位批量路径。加入第八项大块内存负载；基线也运行完全相同的新负载，使用旧后端及独立保存的旧 runtime 源码快照，避免把新库误当成旧库。所有比较均为 O1，校验值与主机 C 相同。

| 负载 | 本轮前指令数 | 本轮后指令数 | 减少 |
| --- | ---: | ---: | ---: |
| 整数算术 | 4,895 | 4,895 | 0.0% |
| 分支与循环 | 9,230 | 9,230 | 0.0% |
| 数组遍历 | 10,464 | 10,464 | 0.0% |
| 函数调用 | 3,878 | 3,622 | 6.6% |
| 递归 | 14,460 | 12,134 | 16.1% |
| 字符串与 libc | 175,663 | 155,759 | 11.3% |
| 设备输出 | 801 | 801 | 0.0% |
| 大块内存 | 181,532 | 104,962 | 42.2% |

本轮大块内存负载的数据访存从 26,103 次降到 8,949 次，代码从 916 字节增至 1,624 字节；字符串负载代码从 3,224 字节增至 3,500 字节。批量路径以更大代码体积换取大块操作效率，短拷贝存在路径选择开销。其余基准没有测得指令数退步，不代表所有程序都能得到相同收益。这些仍是目标执行器统计，未测实机耗时。

[本轮基线 JSON](../benchmarks/results/call-memory-before.json) 与 [本轮结果 JSON](../benchmarks/results/call-memory-after.json) 记录编译器及 runtime 源码哈希。历史基线可直接从已保存的 JSON 比较。

```bash
python3 tools/benchmark.py --output build/call-memory-opt/after.json --compare benchmarks/results/call-memory-before.json
```

已有七类基线缺少新 memory 负载时，比较工具明确标记为无基线，其余共同负载照常对比。O3 的八类目标计算也通过主机校验；库的对齐/长度/保护字节检查在 O1/O2 下通过，并补充了高频值跨八参数间接调用的回归。第一轮记录中的“调用点拆分尚未实现”是当时状态，现已由上述实现补上；callee-saved 分配仍未实现。

### 甜甜圈专项复测

本轮前后均用 O3、低 64 KiB 布局、关闭诊断，计算前两帧并逐字节比较画面和深度缓冲。本轮前使用 当时的后端和运行库快照：12,315,432 条；本轮后使用当前后端和当前 runtime：12,229,652 条。减少 85,780 条，约 0.70%。额外对照“旧后端 + 新 runtime”同样为 12,229,652 条，因此这个例子本轮收益来自 memcpy/memset，调用点保存优化没有额外减少指令数。不能将大块内存基准的 42.2% 套用到甜甜圈。相较第一轮指令选择优化后的 O3 记录 14,122,103 条，当前累计减少约 13.4%；这仍是重新编译版本的指令数，不是实机耗时。

复测命令：

```bash
python3 tests/test_donut.py --low-memory --opt 3 --artifacts build/call-memory-opt/donut-after
```
