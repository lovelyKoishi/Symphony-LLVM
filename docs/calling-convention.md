# 调用约定与 LLVM 约束

本页保留第一阶段的事实与设计约束。第二阶段已经选定的实际 ABI 及实现范围见 [backend.md](backend.md)。

## 1. 已存在的机制不是完整 ABI

硬件只提供寄存器、内存、PC 和基础指令。当前 `call/ret/push/pop` 的展开建立了向下增长、每项 4 字节的栈与返回地址机制。它们没有规定以下事项：

- 参数如何分配、超过寄存器数量后如何放栈。
- 哪些通用寄存器由 caller/callee 保存。
- C 的整数/指针宽度、结构体布局、对齐、聚合返回与变参。
- 堆、栈、framebuffer、持久内存的区域划分。
- `main` 参数、返回后的行为、标准库和链接方式。

因此不能从 `name="Symphony"` 推出一个现成、唯一的 C ABI。第一阶段只固定已有事实与实现约束，**没有宣布一个已实现的 LLVM ABI**。

## 2. 游戏函数关卡的示例约定

来源 **GAME-ABI** 文件开头：

| 用途 | 约定 |
| --- | --- |
| 两个参数 | `r1`, `r2` |
| 函数结果 | `r1` |
| caller 可被覆盖的通用寄存器 | `r1`, `r2` |
| 其他通用寄存器 | 使用后由 callee 恢复 |
| sp | push/pop/call/ret 配对，返回时恢复到 caller 预期位置 |
| flags | `call/ret` 必然覆盖，不可作为跨调用保留的比较状态 |

关卡注释笼统说除 r1/r2 外都保留；从当前 call/ret 编码可知 flags 是必须单独列出的例外。不要按注释字面要求 ret 同时保留 flags，这与定义冲突。

这是教学示例约定，不是硬件只允许两个参数。参数和返回值可以另定协议，但调用双方必须一致。示例代码本身也不能代替完整 C 启动/退出运行时。

该项目使用 `r1..r6` 作为最多六个实参/表达式临时寄存器，结果在 r1；Melody 局部值分配到 `r7..r12`，非 main 函数保存其使用的局部寄存器。它不是游戏 r1/r2 示例约定的原样实现。

其 LLVM 转换器为字符串解析方式，只支持有限 IR；alloca 被当作寄存器槽处理，临时寄存器数量有限，不能拿它作为完整 Clang IR 或内存布局的证明。该仓库 README 也明确列出不支持一般乘除、自动栈溢出、通用指针等限制。当前本地新增硬件指令必须以 `isa/spec.isa` 为准，不能沿用上游“没有乘除”的假设。

后续应参考其语法和设备接口，但要重新处理真实栈帧、参数存活、递归、溢出、指针和 Clang 类型语义。也不能把其所有输出都假定为经过当前硬件验证的汇编。

## 4. 后续 LLVM 后端必须满足的约束

### 4.1 数据布局

必须先定义目标 C ABI，再让 frontend 与 backend 使用一致的数据布局。

- 机器寄存器为 32 位，字节为 8 位，主内存多字节值为**大端**。
- 32 位地址寄存器不自动意味着 C 指针类型已经定为 32 位；建议采用 32 位指针以完整表达现有寄存器寻址，但这是后续 ABI 设计选择。
- `int/long/long long`、指针、结构体、数组步长、位域和对齐必须一起确定，不能看到 ALU 32 位就宣称已经支持所有 C 类型。
- 不能拿 x86_64 IR 的 64 位指针与 `long` 直接截断；也不能仅替换 `target datalayout` 字符串来“修正”已经由小端目标做过布局相关优化的 IR。
- 借用其他 frontend target 时，需要验证其字节序、C 类型尺寸、对齐和 ABI lowering；当前阶段未选定替代 target。

### 4.2 算术与类型

`i8/i16` 运算结果需要在 LLVM 规定的位宽上截断；不能让 32 位寄存器中的高位污染后续比较。`sext`、`zext`、`trunc` 必须分别实现。`load_8/load_16` 只有零扩展。

有符号比较使用 S 位，无符号比较使用 U 位；算术右移使用 `asr`，逻辑右移使用 `lsr`。`sdiv/srem` 必须对无符号硬件 `div/mod` 作符号处理，余数符号跟随被除数。`INT_MIN/-1` 的 LLVM/C 未定义情形与硬件除零行为分开处理。

32 位低半乘法可直接选 `mul`；64 位乘法、高半乘法、溢出检测内建函数不能据此宣称原生支持。

### 4.3 控制流与调用

- 只有绝对 U16 直接分支；超过范围的块必须诊断或展开，不能截断地址。
- 函数指针/间接 call 没有当前文本别名；需要显式构造返回地址再 `jmp register` 等序列。
- flags 在 call/ret 后失效；不能跨调用复用先前比较。
- 递归和嵌套调用必须有每次调用独立的栈帧，不能把所有函数的局部值放到固定共享地址。
- 参数赋值必须处理寄存器间的并行搬运冲突；不能逐个覆写仍需读取的源寄存器。
- `phi` 需要边上的并行复制或正确栈化；不能在块入口无条件执行多个 incoming 赋值。
- 栈上的返回地址、callee 保存值、局部槽和传出参数不能重叠；SP 恢复路径包括每一个 return。

### 4.4 启动、内存和库

编译器必须提供明确入口，显式设置 sp 与需要的运行时状态。main 返回后应进入约定的退出路径；硬件没有天然“main 返回就停机”。

必须规划程序/全局变量、framebuffer、栈、堆区域；保留主内存 24 位物理回绕事实，防止两个不同 32 位指针静默指向同一物理地址。现有测试的 `0x8000` framebuffer 与 `96×40` 只是程序布局，不能强制成为全部 C 程序的 ABI。

标准 C I/O、malloc、浮点、变参、结构体返回、64 位运算和原子操作需要库或明确的未支持诊断。第一阶段不声明它们已完成。

## 5. 阶段边界

本阶段不决定是否完整移植 LLVM Target/TableGen/MC/Clang/lld，或先实现独立的 LLVM IR 后端。两条路径都必须服从本文固定的硬件和汇编语义。应先完成 [sources-and-status.md](sources-and-status.md) 的边界验证，再确定 ABI 与实现方案。
